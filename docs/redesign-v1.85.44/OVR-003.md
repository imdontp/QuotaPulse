# OVR-003 reconciliation

Authority: blueprint v1.1 `11_REFERENCE_OVERRIDES.md`, OVR-003 requires counts
derived from selected scope. The v1.85.43 audit identified the former global
sidebar as a contract gap. OVR-002's static machine workspace label does not
exempt those counts.

The scoped endpoint and committed page-scope propagation now implement that
requirement on Overview, Live, Projects, Models, Cost and History. Provider,
Alerts and Settings pages have no recorded-usage filter and retain machine
counts with the existing explicit explanation. Current quota risks and daemon
connection are independent of recorded-usage scope.

Evidence:

- `packages/daemon/test/runtime-summary.test.ts`: legacy response, scoped
  deduplication, metadata-only exclusion, sessionless inclusion, filter/range
  boundaries, recent observation, strict parsing and authentication.
- `packages/web/test/quick-stats-scope.test.ts`: complete-scope destination
  compatibility, aliases and unsupported actions.
- [Production browser](quickstats-verification.json): actual delayed A/B/A,
  pending count state, committed History drafts, pre-pause response rejection,
  History/Live freeze and resume, and old machine scope.
- [EN/Dark all-page capture](capture-verification.json): sidebar counts compared
  with scoped daemon responses; unchanged shell geometry and contrast checks.

The explanatory note still discloses the five-minute session observation
limitation. No unknown identity is invented. No-query API defaults preserve old
clients. Unsupported scoped count labels have no link; global navigation still
provides access to every page.

This closes the demonstrated implementation gap with automated evidence.
It does not approve the full 23-override ledger, screen-reader behavior, original
reference likeness, final four-variant visual baseline, or release readiness.
The [historical full audit](../redesign-v1.85.43/OVERRIDE-COVERAGE.md) remains a
record of its original build, with this document supplying the current scope fix.
