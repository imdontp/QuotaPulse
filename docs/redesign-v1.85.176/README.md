# Long-path installer and actual two-version rollback / source176

The review installer failed to extract an actual archive when Windows long-path policy was disabled and a staging file reached 262 characters. Windows extended-path file I/O succeeded, while .NET `ZipFile.ExtractToDirectory` rejected that prefix. The installer now retains ZIP path validation and streams entries into its fresh stage with extended paths. An independent regression installed a synthetic ZIP entry at 351 characters, and rejected traversal and embedded review-data before creating a destination.

A second test exposed an Electron executable at 266 characters: Windows PowerShell could not launch it even when the file existed under an extended path. Before making any destination changes, the installer now rejects an Electron executable path of 260 characters or longer with an instruction to choose a shorter destination. This prevents claiming an installation can run at that tested path; it is not proof that every shorter destination works.

Actual ZIPs review163 (source162) and review174 (source173) were bound to their committed delivery receipts, archive hashes and every runtime byte. In an isolated profile with readers off, the test installed the earlier version, upgraded to the later version, rolled back, and returned to the later version. Each of four stages verified the installed runtime inventory, served web bytes, actual daemon/tray process identity and termination, and identical schema7, source/session/usage/pricing, app/notification settings and window-size snapshots. The fixture source is explicitly disabled to match readers-off operation; an earlier run correctly exposed that the first fixture incorrectly seeded an enabled source.

The initiating installer is the fixed local source; the two archived applications and their installed rollback wrappers are the original ZIP contents. Review174 therefore does not contain the installer correction. The source was line-ending-normalized after the four-stage run; its LF-normalized SHA matches the installer exercised there, and the targeted regression passed again with the final CRLF file.

This does not establish browser/native UI readiness during rollback, Electron localStorage preference preservation, different-schema migration, real account/provider behavior, physical monitor or performance acceptance. The ZIPs remain unsigned reviews. Five duplicate QA runtime trees were byte-verified and cleaned, reclaiming 1,814,182,552 bytes; 444,292 ASAR bytes remain. Synthetic profile and evidence files are retained. The full redesign goal remains active.
