# Projects and Models: denser comparison and readable values

[Open the comparison](review.html). The application images are from the production web build and an isolated in-memory database containing 504 synthetic records across six projects, twelve model/provider pairs and seven days. The screenshots use English/dark at 1672 × 941, DPR 1, with a fixed clock and reduced motion. Both captures repeated byte-for-byte. The concept images are the previously manifest-verified originals. Synthetic data and the approved blueprint's replacements for unsupported budgets, benchmark metrics and other invented content make the values, chart shapes and text different from the concept. This gallery is a review aid, not a fidelity or acceptance score.

The denser fixture exposed a Models summary value breaking inside `$0.32` at the reference viewport because its column shared a fixed-width grid with the sparkline. The summary grid now assigns the figure its natural width before the chart receives the remaining space. Forty API-backed cases checked one-line normal values, card containment, chart separation and page overflow for English/Thai, dark/light, USD/THB and five widths from 390 to 1672px.

It also exposed isolated priced observations that were nearly invisible in a small sparkline: unknown buckets correctly break lines, but a single-point run had no visible line and its marker shrank with the SVG viewBox. Isolated points now receive a non-scaling stroke; no line is drawn across unknown buckets. The seven synthetic points were checked against the underlying database sum and each remains a separate run.

The production web build and 380 web tests passed. Models and Projects each passed four English/Thai and dark/light capture pairs; all eight pairs were byte-identical. The dense Models screenshot still places the bottom rows inside the scrollable table; the concept displays its full set within the visible frame. Project icon choices and data-dependent charts also differ. These remain review and implementation work, and this comparison does not establish whole-dashboard visual fidelity. Review211 predates this change; real providers, physical desktop/tray testing, cross-schema migration, production performance and the previously intermittent Runtime Map issue remain open.
