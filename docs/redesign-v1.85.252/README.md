# Transcript continuity warning

Codex and Claude Code skip a transcript that has the same size as its fully consumed cursor. Previously, changing the contents without changing that size still produced no warning even if the filesystem modification time changed. Two targeted synthetic tests reproduced this: both readers skipped the changed file and Diagnostics reported no unverified file.

When a fully consumed, nonempty transcript has the same size but a different modification time, the readers now preserve its existing cursor and mark its earlier history unverified. The metadata update does not advance the cursor, update the last successful read, clear an existing error or alter stored usage. The flag persists across later appends and database reopen. English and Thai Diagnostics explain that a timestamp change alone does not prove loss: a timestamp-only touch produces the same conservative warning even if the bytes are identical. No transcript paths or raw transcript content are included in the warning aggregate.

Daemon and web builds passed. The final daemon suite passed 155 tests and the web suite 382 tests. Four focused cases cover both readers, same-size changes to actual usage numbers, timestamp-only touches, preservation of stored values and error state, unchanged files, a later clean append and restart. Ten compiled browser cases cover API warnings, both languages and themes, 390/1440px, and the fallback for an older daemon. All test transcripts are synthetic. Logs, the source/build hashes and the separate limitation probe are retained in `evidence.tar.gz` and `verification.json`.

This is a warning, not automatic recovery or proof of loss or completeness. A separate controlled probe changed a usage number while restoring both file size and modification time: neither reader warned. Earlier bytes changed before a later growth, changes predating this version, incomplete discovery, other adapters and source-side omitted events are also not proven complete by this check. Cost's monthly projection remains unavailable under the blueprint until complete, fresh call-grain data can be substantiated. The existing Vite large-chunk warning remains. Review249 predates this change; the overall redesign goal remains open.
