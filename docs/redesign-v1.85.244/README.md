# Review236 ↔ review243 upgrade and rollback

The actual delivered [review236](../redesign-v1.85.236/README.md) and [review243](../redesign-v1.85.243/README.md) ZIPs were checked against their committed delivery evidence and archive SHA-256 before the test. Their source commits are `194cafb367afec214960b655bad238dc1d32a277` and `d71aa1480af0b9f332ebf757a3c37f0761628a1e`, respectively. The review243 delivery README bound by the provenance is its version at commit `ade51fe`, before this follow-up updated that README. All testing used a newly created isolated installation and schema 7 profile with readers disabled.

The first run passed the initial, upgrade and rollback stages, but the last stage timed out after 15 seconds waiting for the native Electron close event. Its screenshot had already been captured; the stage was not reported as passed and its final snapshot was not recorded by that run. No process referring to the fixture remained when inspected. The exact cause of the close timeout is unknown; this is not a claim that a product or test defect was fixed. Retrying the same final stage on that fixture passed, and its subsequent durable snapshot matched the initial baseline.

A second, fresh end-to-end run passed all four stages in sequence: review236, upgrade to review243, rollback to review236, then return to review243. At every stage, the installed release's runtime matched its archive-derived inventory, the isolated daemon and tray started with readers off and stopped, and the durable snapshot of schema, sources, sessions, usage including null/empty distinctions, pricing, app/notification settings and window size matched the initial snapshot. A separately launched offscreen native Dashboard verified persisted Thai language, light theme, THB currency, exchange rate 37.25 and window size 1371×887. The native check uses test-only anti-occlusion settings and reduced motion.

Both test fixtures' four runtime copies were checked byte-for-byte against the retained ZIPs, checked for live fixture processes and cleaned. This reclaimed 1,814,357,830 bytes; synthetic profiles and four small ASAR residues remain, so those test installations need runtime restoration before reuse. Both retained ZIP hashes were rechecked afterward. `evidence.tar.gz` contains provenance, the failed run, the separately retried final stage, the successful full run, native captures and cleanup receipts; the short failure transcript was transcribed from the tool output.

This validates the stated path on one synthetic schema 7 profile, not cross-schema migration, real provider accounts, physical tray interaction, production performance or whole-dashboard visual acceptance. The redesign goal remains open.
