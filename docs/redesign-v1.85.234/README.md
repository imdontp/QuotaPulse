# Alerts quota history during a reader switch

When the freshest reader for the same quota owner and window changed, Alerts retained its previous history until the new request completed. A controlled local reproduction showed the current risk value at 97% while the main graph and row sparkline still displayed the previous reader's 60%, 70% and 80% samples. This could associate one reader's history with another reader's current value.

Alerts now checks the owner, window, source, origin and reset period before showing cached history. The reset comparison retains the existing two-second jitter tolerance. If the cached history belongs to a different reader or reset period, the main graph shows a localized refresh message and the row sparkline shows unavailable until matching history arrives. A failed history request remains retryable; a same-reader older history can still be shown with its existing stale/error handling. No quota samples or forecast values are manufactured.

The compiled-browser reproduction uses two real local API readers backed by an isolated synthetic SQLite database and deliberately holds the history request. Before the change it observed the old graph and sparkline beside the new 97% reading. After the change, both were withheld, the correct history appeared when the request was released, and a second switch with a synthetic 503 recovered after the user pressed retry. This passed in eight English/Thai, dark/light and 390/1440px cases. Unit coverage includes owner, window, source, origin, reset jitter and readerless responses. Web build and 382 tests passed.

The Alerts stable-capture suite and its interaction/responsive checks passed against the final compiled build. Three of four unmasked English/Thai and dark/light screenshot pairs were byte-identical; one differed by one pixel with a maximum channel delta of one. Results and the failed-before reproduction are retained in `evidence.tar.gz`. This verifies the stated synthetic transitions, not real provider behavior, full motion performance or the overall 99–100% visual target. Review230 predates this change.
