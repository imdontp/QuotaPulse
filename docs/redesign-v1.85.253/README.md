# Transcript change-time observation

[Checkpoint252](../redesign-v1.85.252/README.md) warns when a fully consumed transcript keeps its size but changes modification time. Its separate probe showed that a same-size edit with the old modification time restored was not detected. On this Windows filesystem, that controlled edit changed the file's change time (`ctime`) even though size and modification time were restored.

Codex and Claude Code now save the observed change time with the cursor and treat a changed modification or change time at the same fully consumed size as uncertainty. Existing cursors without change-time metadata receive a forward-looking baseline, without advancing the cursor, clearing an error or claiming a successful read; the baseline does not verify past bytes. Timestamp or metadata changes alone do not prove data loss. The warning is still aggregated without transcript paths or content, and retained usage is not rewritten.

During review a separate synthetic two-store interleaving demonstrated that a stale metadata update could overwrite a newer model value. Metadata updates now compare the observed cursor and raw metadata atomically; on a conflict they leave the newer state intact and invalidate the local cache for a later pass. The regression also covers another metadata-only update at the same offset. A conflict may defer an observation, so it is not proof that all concurrent changes are detected.

Daemon and web builds passed; the final daemon suite passed 160 tests and web suite 382. Nine focused cases cover both readers, restored modification time where change time differs, old cursor baselines, same-size edits, timestamp-only touches, and concurrent cursor/metadata updates. The four new change-time tests and the concurrency test failed before the fix. Ten compiled browser cases cover Diagnostics, both languages and themes, 390/1440px, older-daemon fallback and the restored-mtime fixture. All inputs are synthetic. The single local SQLite WAL benchmark updated and verified 5,000 metadata rows in 198.5 ms on this machine; it did not scan files and is not production performance certification. Logs, hashes, before/after probes and benchmark driver are in `evidence.tar.gz` and `verification.json`.

This is a conservative warning, not automatic repair, proof of lost data or a complete source contract. Filesystems may not expose distinct change times; changes before the first baseline, changes to old bytes followed by growth before a pass, and source-side omissions remain unverified. Cost's monthly projection remains unavailable until the blueprint's completeness and freshness conditions can be proved. Review249 predates this change; the overall redesign goal remains open.
