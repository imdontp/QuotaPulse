# Actual review191 ↔ review194 upgrade and rollback / checkpoint196

The actual archived Windows review191 (`20ebfd4aa692249b1f85ba9751a901fe7a8d9ddd`) and review194 (`f14d872f4acd28410c08868781ded98538ced64a`) were verified against their delivery receipts and every installed runtime byte. In a fresh isolated profile with readers disabled, four stages passed: previous, upgrade to current, rollback to previous, and recovery to current. Each checked active release identity, daemon/tray process identity and termination, every served web asset, schema7 facts and null/empty values, pricing, app/notification settings, and the durable window-size snapshot.

At each stage, after the installed-wrapper processes stopped, the actual Electron tray/dashboard was separately launched from that stage's installed release using the same isolated profile and daemon. The first stage set Thai, light theme, THB, rate 37.25 and 1371×887 through the UI. Every subsequent stage verified these values in persisted storage and rendered UI, and verified the actual window size. Live metrics had loaded before capture; the [post-upgrade native Settings capture](current-upgrade.png) shows the restored values. Windows were offscreen, nonfocusable, reduced-motion and used test-only anti-occlusion flags; these are not physical-monitor, tray-click or performance tests. Capture retries were available but no retries were needed in the final four stages.

Two earlier attempts are retained as limitations: the first native helper assumed an initial dark theme and failed when the system began light; a later attempt encountered one `UnknownVizError` during offscreen capture. A prior successful attempt captured a stale loading frame before paint; the final attempt waits for loaded metrics and rendering. These observations do not establish an underlying Electron cause or production smoothness.

The earlier fixture also exposed a distinct Settings inconsistency: with `window-size.json` set to 1371×887 and no matching browser-local window-size setting, the actual Electron window was 1371×887 but the Settings fields showed the default 1080×860. [The isolated capture](size-disagreement.png) records that state. Source inspection shows the native window and Settings initialize from different stores. This is an observed mismatch for that deliberately inconsistent profile, not evidence about its frequency in user installations. The later source fix and its separate tests are recorded in [checkpoint197](../redesign-v1.85.197/README.md); the older review archives tested here still contain the original behavior.

Across the exploratory attempts and final run, nine duplicate runtime trees were byte-verified against their ZIPs and cleaned, reclaiming 4,082,028,492 bytes; small ASAR residues, synthetic profiles and evidence were retained. This test covers the same schema7, not a cross-schema migration, real reader/account setup, production signing or full visual acceptance. Review194 predates History change `07035e4`; the latest application source has not yet been packaged for this test. The goal remains active.
