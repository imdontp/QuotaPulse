# Overview quota history across reset periods

When a selected quota's reset changed but its owner, window and reader stayed the same, Overview retained the previous history response until a new one arrived. With a deliberately held API request, the pre-change compiled app showed the new 97% reading alongside only the old period's 60%, 70% and 80% points. `before.log` retains the failed reproduction; it used an isolated synthetic database.

Overview now checks owner, window, source, origin and reset period before displaying the response, using the same matching rule as Alerts. A reset change with a matching reader hides the old response while the new one loads. A successful response with the wrong identity is treated as unavailable. Reset jitter of up to two seconds stays in the same period. When a matching response arrives, its actual prior and current reset segments are all retained; no samples are fabricated or discarded from that response. The raw nullable reset is preserved separately from the existing presentation fallback. Failed requests remain unavailable until a subsequent successful refresh.

Web build and 382 web tests passed. `matrix.json` records eight compiled browser cases across English/Thai, dark/light and 390/1440px: each exercises the held reset transition, real historical segments, same-period jitter, a 503 and recovery, and a successful but old API payload and recovery. The first expanded test checked too early for the intercepted request; it was corrected to wait for the request to be held, and the complete matrix then passed. `alert-regression.log` records an additional Alerts reader-switch, failure and retry pass after moving the identity check into shared code. `npm run test:ui` passed navigation, filters, empty/error/recovery, responsive Live/Limits and existing popup checks.

The canonical English/dark Overview capture with matching history is byte-identical to checkpoint238 and its repeated capture; `capture-verification.json` records the compiled index hash. This verifies the specified synthetic transitions and stable frame, not live provider behavior, production performance or whole-dashboard visual acceptance. Review236 predates this change.
