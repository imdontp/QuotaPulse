# History chart scale for zero and small values

The History chart previously forced its vertical maximum to at least one and rounded every tick to a whole token. For a zero-input/output fixture this displayed repeated `0` and `1` labels even though no positive value was plotted; a maximum of one also collapsed distinct quarter-scale labels. The chart now shows only a zero label for an all-zero series, uses the recorded maximum for a positive series, and falls back to sufficient precision when the normal compact formatting would merge labels. The horizontal grid and underlying API facts remain unchanged. Non-finite input does not receive a fabricated zero label.

The web build and 379 web tests passed. A compiled-browser test passed 48 English/Thai, dark/light, narrow/desktop cases against an isolated API/database, covering zero, 1, 2, 0.5, 0.000001 and 1,000,000 tokens. It checked API-derived tick values, distinct text, actual plotted positions, label containment and page overflow. History's normal and selected states passed eight screenshot pairs: six were byte-identical and two Thai/light pairs differed within the existing unmasked raster tolerance. `npm run test:ui` passed, including the legacy and popup checks.

[Zero-value example](history-axis-0.png) and [one-token example](history-axis-1.png) are synthetic screenshots, not reference-parity evidence. During the probe, changing the source preserved an earlier selected detail record even when it was absent from the new page; the application deliberately retains the original selection/scope for its related link, but the lack of an explicit out-of-page indication needs separate assessment. The screenshots explicitly select the current row. The saved review211 ZIP predates this change. Whole-dashboard concept fidelity, real providers, physical tray/display behavior, cross-schema migration, production performance and the intermittent Runtime Map issue remain open.
